## 问题 1：swiper 组件导致渲染层错误

### 问题描述
- 错误信息：`[渲染层错误] Expected updated data but get first rendering data`
- 影响范围：使用 swiper 组件的页面（首页、详情页）
- 严重程度：高 - 可能导致其他页面（地图页、用户页）无法正常显示

### 原因分析
在 uni-app x (uvue) 的微信小程序编译中，`swiper` 组件存在兼容性问题，会触发渲染层错误。该错误不仅影响当前页面，还可能导致整个小程序的 tab 切换和其他页面渲染异常。

### 解决方案
使用 `view` + `transform: translateX()` + `setInterval` 手动实现轮播效果，完全替代 `swiper` 组件。

### 实现代码
```html
<view class="banner-viewport">
  <view class="banner-track" :style="{ transform: 'translateX(' + (-currentBanner * 33.333) + '%)' }">
    <view class="banner-item" v-for="(banner, index) in banners" :key="index">
      <image :src="banner.image" mode="aspectFill"></image>
    </view>
  </view>
</view>
<view class="banner-dots">
  <view class="banner-dot" v-for="(b, i) in banners" :key="i" :class="{'banner-active': i === currentBanner}"></view>
</view>
```

```css
.banner-viewport {
  width: 100%;
  height: 420rpx;
  overflow: hidden;
}

.banner-track {
  display: flex;
  flex-direction: row;
  width: 300%;  /* 3张图片，每张33.333% */
  height: 100%;
  transition: transform 0.5s ease;
}

.banner-item {
  width: 33.333%;
  height: 100%;
  flex-shrink: 0;
}
```

```javascript
import { ref, onMounted, onUnmounted } from 'vue'

let bannerTimer = null
const currentBanner = ref(0)

const startBannerAutoPlay = () => {
  if (bannerTimer) clearInterval(bannerTimer)
  bannerTimer = setInterval(() => {
    currentBanner.value = (currentBanner.value + 1) % banners.length
  }, 4000)
}

onMounted(() => startBannerAutoPlay())
onUnmounted(() => {
  if (bannerTimer) clearInterval(bannerTimer)
})
```

### 经验教训
- 在 uvue 中尽量避免使用 `swiper` 组件
- 手动实现轮播的关键：viewport(overflow:hidden) + track(flex+transition) + transform
- 轨道宽度 = 图片数量 × 100%，每张图片宽度 = 100% / 图片数量
- 移动距离百分比 = 当前索引 × (100 / 图片数量)

3. banner 的 id 没有正确映射到详情页数据

1. 扩充详情页数据，确保包含所有首页入口的项目

## 问题 3：轮播图只显示一张图片

### 问题描述
自定义轮播图实现后，只能看到第一张图片，切换时图片不滚动。

### 原因分析
`banner-track` 的宽度设置为 `100%`，导致 flex 子元素被压缩或溢出不可见。

### 解决方案
将 track 的宽度设置为 `图片数量 × 100%`，每张图片的宽度设置为 `100% / 图片数量`。

```css
.banner-track {
  width: 300%;  /* 3张图片 */
}

.banner-item {
  width: 33.333%;  /* 100% / 3 */
  flex-shrink: 0;
}
```

对应的 transform 移动距离也要调整：
```javascript
// 移动距离 = 当前索引 × (100 / 图片数量)
transform: translateX(-currentBanner * 33.333%)
```

### 经验教训
- 轮播图实现的核心是：viewport + track + items 的宽度比例关系
- track 宽度 = n × 100%（n 为图片数量）
- 每张图片宽度 = 100% / n
- translate 百分比是相对于 track 自身宽度的

## 问题 4：uvue 模板中使用 JavaScript 方法导致渲染问题

### 问题描述
在 uvue 模板中使用 `Math.floor()`、`charAt()`、`slice()` 等 JavaScript 方法，可能导致渲染异常或报错。

### 涉及位置
1. 详情页：`Math.floor(detail.rating)` - 用于星级评分
2. 用户页：`userInfo.nickName.charAt(0)` - 用于头像首字母
3. 用户页：`userInfo.openid.slice(-8)` - 用于用户ID显示

### 解决方案
将模板中的复杂表达式移到 `computed` 计算属性中，模板只使用简单的变量绑定。

```javascript
import { ref, computed } from 'vue'

const ratingInt = computed(() => {
  const r = parseFloat(detail.rating)
  if (isNaN(r)) return 0
  return Math.floor(r)
})

const avatarText = computed(() => {
  const name = userInfo.value.nickName
  if (!name || name.length === 0) return '游'
  return name.charAt(0)
})
```

### 经验教训
- uvue 模板中尽量只使用简单的变量和运算符
- 复杂计算（方法调用、字符串处理、数学运算等）移到 computed 中
- 养成"模板只做展示，逻辑放 script"的习惯

## 问题 5：flex 布局在 uvue 中不生效

### 问题描述
设置了 `display: flex` 但元素还是垂直排列，没有水平排列。

### 原因分析
uni-app x (uvue) 的 flex 布局默认 `flex-direction: column`（垂直方向），与 Web 开发中的默认值（row）不同。

### 解决方案
所有需要水平排列的 flex 容器，都要显式设置 `flex-direction: row`。

```css
.quick-entry {
  display: flex;
  flex-direction: row;  /* 必须显式设置 */
  flex-wrap: wrap;
}
```

### 经验教训
- uvue 中 flex 默认为 column，需要水平排列必须显式加 `flex-direction: row`
- 这是 uvue 和普通 Web 开发的重要区别之一
- 遇到 flex 不生效，先检查是否设置了 `flex-direction: row`

## 问题 6：微信小程序背景图无法使用本地资源

### 问题描述
错误信息：`wxss 中的本地资源图片无法通过 WXSS 获取`
使用 `background-image` 引用本地图片路径，在微信小程序中不显示。

### 原因分析
微信小程序的 WXSS 限制了本地背景图片的使用，只能通过网络图片或 base64 方式。

### 解决方案
将 `background-image` 改为 `<image>` 标签，用绝对定位实现背景效果。

```html
<!-- 之前 -->
<view class="banner" style="background-image: url('/static/banner.jpg')"></view>

<!-- 之后 -->
<view class="banner">
  <image src="/static/banner.jpg" mode="aspectFill" class="banner-bg"></image>
  <view class="banner-content">...</view>
</view>
```

```css
.banner {
  position: relative;
}
.banner-bg {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
}
.banner-content {
  position: relative;
  z-index: 1;
}
```

### 经验教训
- 微信小程序不支持 WXSS 中的本地背景图片
- 用 `<image>` + 绝对定位替代 `background-image`
- 设计时就避免依赖背景图的实现方式

## 问题 7：横向滑动（scroll-view）不响应

### 问题描述
scroll-view 设置了 `scroll-x="true"` 但无法横向滑动。

### 原因分析
uvue 中 scroll-view 的横向滚动需要配合正确的内容布局：
1. scroll-view 需要固定高度
2. 内容容器需要 `white-space: nowrap`
3. 子元素需要 `display: inline-flex` 或 `inline-block`

### 解决方案
```css
.scroll-container {
  width: 100%;
  white-space: nowrap;
}

.scroll-content {
  display: inline-flex;
  flex-direction: row;
}
```

### 经验教训
- scroll-view 横向滚动三要素：固定高度 + nowrap + inline 子元素
- 如果不行，先检查子元素是不是被换行或者宽度不够

## 图片批量处理脚本

### 使用场景
需要将桌面的大量非遗图片批量复制并重命名到项目 static 目录。

### PowerShell 脚本模板
```powershell
$src = "C:\Users\34091\Desktop\images"
$dst = "c:\Users\34091\Desktop\uni app\非遗 支付宝云\static"

$mappings = @(
    @{ Src = "敦煌彩塑制作技艺.jpg"; Dst = "banner1.jpg" },
    @{ Src = "庆阳香包绣制.jpg"; Dst = "banner2.jpg" }
)

foreach ($m in $mappings) {
    $srcPath = Join-Path $src $m.Src
    $dstPath = Join-Path $dst $m.Dst
    if (Test-Path $srcPath) {
        Copy-Item -Path $srcPath -Destination $dstPath -Force
        Write-Host "✅ $($m.Dst) <- $($m.Src)"
    } else {
        Write-Host "❌ 找不到: $($m.Src)"
    }
}
```

### 检查图片文件脚本
```powershell
$staticDir = "项目static目录路径"
$files = @("banner1.jpg", "spot1.jpg", "...")

foreach ($f in $files) {
    $path = Join-Path $staticDir $f
    if (Test-Path $path) {
        $size = (Get-Item $path).Length
        Write-Host "✅ $f ($size bytes)"
    } else {
        Write-Host "❌ $f 不存在"
    }
}
```

## 开发流程最佳实践

### 1. 数据优先
在开发列表+详情的页面时，先规划好：
- 有哪些入口（列表、banner、推荐等）
- 每个入口对应的 id
- 详情页需要包含哪些数据
- 统一命名和数据结构

### 2. uvue 开发注意事项
- flex 布局必须显式指定 `flex-direction: row`
- 模板中避免复杂表达式，用 computed 替代
- 尽量避免使用 swiper 等有兼容性问题的组件
- 图片用 `<image>` 标签，不用 background-image

### 3. 问题排查顺序
页面不显示时，按以下顺序排查：
1. 控制台有没有报错
2. 是不是用了 swiper 组件
3. 模板中有没有复杂的 JS 方法调用
4. 数据有没有正确绑定
5. flex 布局有没有加 `flex-direction: row`

### 4. 图片资源管理
- 建立清晰的命名规范（banner1.jpg, spot1.jpg 等）
- 批量复制时用脚本，避免手动复制出错
- 复制完成后用脚本检查所有文件是否存在
